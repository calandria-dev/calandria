# Design System: Calandria

## Overview

**Creative North Star: "Quiet control room"**

Calandria combines compact task lists, readable session transcripts, and persistent status indicators. Serif headings establish the major surfaces. Sans-serif controls and monospaced technical details keep the workspace easy to scan.

This document captures the current application. The north-star phrase is provisional descriptive language. The implementation establishes the tokens and component behavior.

**Key Characteristics:**

- Dense desktop panes and a single active pane on phones.
- Four selectable palettes, each with dark and light modes.
- Tonal surfaces, fine borders, and rounded controls.
- Accent selection states and separate running, attention, and error signals.

Use [app/globals.css](app/globals.css) as the implementation source and [the design handoff](docs/design/handoff/README.md) for the original visual references. Font loading lives in [app/fonts.ts](app/fonts.ts); appearance preferences live in [usePrefs.ts](app/shell/usePrefs.ts). Committed [desktop](docs/images/workspace.png) and [mobile](docs/images/mobile.png) screenshots illustrate the composition but can contain older labels. Current source takes precedence.

## Colors

The palette combines restrained backgrounds with a distinct action accent and separate status colors.

### Primary

The unprefixed frontmatter colors capture the default Cherenkov dark palette. Other palettes use `<palette>-<mode>-<token>` names. These names document the theme variants; application CSS continues to use the same semantic custom properties in every theme.

| Palette | Character | Accent |
|-|-|-|
| Cherenkov | Blue-black or cool pale surfaces | Teal |
| Heavy Water | Green-black or pale green surfaces | Coral in dark mode, rust in light mode |
| De Noche | Violet-black or pale violet surfaces | Amber in dark mode, burnt orange in light mode |
| Basic | Neutral charcoal or pale gray surfaces | Blue |

Use `accent` for primary actions, selected controls, links, and focus outlines. The `calandria` token marks the product's chart series; De Noche gives it a distinct pink value.

### Neutral

Use `bg` for the canvas, `panel` for content surfaces, `term` for code and fields, and `line` for boundaries. Use `ink` for primary text and `dim` for secondary metadata.

Derived tokens in the stylesheet adapt to every palette: raised surfaces mix ink into panel, secondary text mixes ink and dim, and selected backgrounds tint the accent. Preserve those `color-mix()` expressions when building components.

### Status and data

- `run` and `run-bg` carry running/completion signals.
- `rev` and `rev-bg` carry review and input-needed signals.
- `err` carries errors and destructive states; `warn` carries warnings.
- `s1` through `s5` provide chart series. Violet also marks agent edits.
- Status labels, icons, and dot shapes accompany color. Lingering and cancelled dots use hollow outlines.

**The Theme Rule.** Use the runtime semantic variables for UI colors. The frontmatter records palette values for documentation and tooling.

## Typography

Self-hosted Spectral supplies display headings. Source Sans 3 supplies body text and controls. JetBrains Mono supplies the default technical text. The frontmatter records their fallback stacks and shared roles.

| Role | Application |
|-|-|
| Headline | Insights titles; the welcome heading also uses a 24px Spectral size |
| Dialog title | Shared modal headings |
| Body | General interface text |
| Control | Shared buttons |
| Label | Uppercase field labels |
| Mono | Code, terminal content, paths, and metadata; size varies by component |

The session title uses 17px bold body text. The onboarding title uses 21px bold body text and becomes 18px on phones. The titlebar wordmark uses 14px Spectral with 0.005em tracking.

Respect the selected code and prompt fonts. Code choices include JetBrains Mono, Fira Code, Cascadia Code, Red Hat Mono, and Atkinson Hyperlegible Mono. Prompt choices include Source Sans 3, Literata, Spectral, and Atkinson Hyperlegible Next. Use the runtime font variables so these preferences remain effective.

**The Type Role Rule.** Keep display type on headings and identity elements. Use body type for controls and task rows, and mono type for technical content.

## Layout

The desktop shell has project, task, and session panes, plus an optional session rail. Default widths are 236px for projects, 352px for tasks, and 430px for the rail. The titlebar is 50px high. Transcript and composer content share a configurable 760px text measure.

Between 761px and 900px, project and task columns narrow to 200px and 300px. At 760px and below, the app shows one full-width pane with mobile navigation. Preserve dynamic viewport sizing, keyboard insets, safe areas, and independent content scrolling. The handoff specifies 44px mobile hit targets; desktop control heights are smaller.

Spacing follows each component's density. The frontmatter spacing entries record reused component measurements; the stylesheet has no single global spacing scale. Shared modal content uses 22px horizontal padding. Task cards use 11px vertical and 13px horizontal padding.

Onboarding uses a centered panel up to 940px wide and 640px tall with a 230px step rail. At the phone breakpoint it fills the viewport, stacks the rail above the content, hides step labels and the tagline, and reduces content side padding to 18px.

## Elevation & Depth

Tonal layers and borders separate the persistent panes. The small shadow appears on task cards and primary buttons. Hovered task cards use the medium shadow. Modals and onboarding use the large shadow. Exact shadow values live in the sidecar and the stylesheet.

The titlebar uses a translucent background and 14px backdrop blur. Onboarding uses a dimmed scrim and 4px backdrop blur. Status glows identify selected activity signals.

Most control transitions take 120ms. Onboarding fades in over 180ms and enters over 220ms; its verification spinner cycles over 700ms. The global reduced-motion rule reduces animation and transition durations to 0.01ms and limits animations to one iteration.

## Shapes

The four shared radius tokens progress from compact controls through containers to large panels. Buttons and fields use `r-sm`, navigation and shared modals use `r`, task cards use `r-lg`, and onboarding uses `r-xl`. Onboarding's CSS fallback is 16px; the active root token resolves to 18px.

Pills group compact metadata and filters. Circular dots and outlined circles communicate task state. Fine borders define fields, panels, and interactive boundaries.

## Components

### Buttons

Primary buttons use accent fill, contrasting canvas-colored text, and the small shadow. Hover applies a 1.06 brightness filter. Secondary buttons use a surface fill and strong border; ghost buttons use secondary text with a transparent background. Both gain a raised surface and primary ink on hover.

Shared buttons use the control size in the frontmatter. Small buttons are 28px high with 10px horizontal padding and 12px text. Disabled buttons have 0.45 opacity and a default cursor. Keyboard focus uses the global 2px accent outline with a 2px offset.

### Inputs and dialogs

Fields use a terminal-colored background, a fine border, body text, and compact rounded corners. Focus changes the border to accent and adds a 3px soft accent ring. Labels sit above fields; hints and validation messages remain adjacent to the affected control.

Shared dialogs are 560px wide with a viewport maximum of `calc(100vw - 40px)` and a height maximum of `calc(100vh - 60px)`. They have separate header, scrolling body, and footer regions, a panel fill, and the large shadow.

### Navigation

Navigation rows use 13px semibold text, a 10px icon gap, and the spacing recorded in the frontmatter. Hover adds a panel fill. Active rows use accent text and a 14% accent tint mixed in sRGB. Mobile settings navigation becomes a horizontal row of bordered controls.

### Chips

Pill controls carry metadata, tags, and filters. Preserve each chip family's status or tag color and its selected treatment. Keep labels visible alongside state colors. Use the existing compact typography and spacing for the specific chip family.

### Task cards

Task cards use a panel surface, a subtle border, and the small shadow. Hover strengthens the border and raises the shadow. Selected cards use an accent border and an inset accent edge. Titles, metadata, status, and task actions retain their separate visual levels.

### Onboarding

The wizard presents “Connect an agent” and “Verify” in a step rail. Active steps use an accent tint and an outlined step number. Completed steps use a checkmark. Connection, verification, and error content occupy the same main panel. Preserve the shared logo, agent connection controls, footer actions, spinner, and explicit success or failure text.

The wizard uses the shared palette and shape tokens. The current terminal-log preview has a local fixed dark treatment; treat it as a component exception when documenting the implementation.

## Do's and Don'ts

### Do:

- **Do** use semantic color and font variables so palette and appearance settings apply.
- **Do** retain visible labels or icons alongside status colors.
- **Do** preserve keyboard focus, reduced-motion behavior, and mobile viewport handling.
- **Do** reuse existing component states and check both dark and light modes.
- **Do** give new component classes a distinct prefix in the flat global CSS namespace.

### Don't:

- **Don't** hardcode the default palette into new components.
- **Don't** apply display typography to every control or task row.
- **Don't** treat desktop button heights as mobile hit-target guidance.
- **Don't** use the generated sidecar tonal ramps as new application tokens.
- **Don't** infer current product behavior from older screenshots.
